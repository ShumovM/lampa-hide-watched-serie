# Плагин Lampa «Убирать просмотренные сериалы»

Файл плагина: [hide_watched_series.js](hide_watched_series.js) (версия 1.1.0, ES5, один файл без зависимостей).

Плагин убирает сериал из строки «Продолжить просмотр», когда все **вышедшие** серии досмотрены,
и автоматически возвращает его, как только выходит новая непросмотренная серия. После просмотра
новой серии сериал снова скрывается. Используется только локальная история Lampa и данные TMDB,
которые запрашивает сама Lampa; Trakt, внешние аккаунты и сторонние серверы не нужны.

## Важно о версиях Lampa

Исходники брались из официального репозитория `github.com/yumata/lampa-source`. Версия **2.3.0** —
это коммиты с `8653d6fa` (12.02.2025) по `6f0aa215` (06.03.2025), дальше идёт 2.3.1. Анализ и
интеграционная проверка выполнены именно на этой версии (собранная копия — `github.com/yumata/lampa`,
коммит `8bd2e9c`).

Отличия 2.3.0 от описания в ТЗ (оно соответствует ветке 3.x):

| | Lampa 2.3.0 | Lampa 3.x (на 28.10.2026 — 3.4.4) |
|---|---|---|
| Файл избранного | `src/utils/favorite.js` | `src/core/favorite.js` |
| `content_rows.js`, `ContentRows.add` | **нет** | есть |
| Где строка «Продолжить просмотр» | раздел **«Сериалы»** (`category`, `url: 'tv'`); на главной её нет | главная и разделы «Сериалы»/«Аниме» |
| Как строится | `tmdb.category()` / `cub.category()` вызывают `Favorite.continues(params.url)` — **свойство** экспортированного объекта | строка `continue_watch` через `ContentRows.add`, внутренняя `continues()` |

LG-приложение Lampa часто загружает актуальный код с сервера, поэтому плагин сам определяет ветку
и работает в обеих (проверено в браузере на собранных 2.3.0 и 3.4.4).

## Как это работает

### Перехват строки (только «Продолжить просмотр»)

- **2.3.0 (режим `legacy`).** В 2.3.0 `tmdb.js`/`cub.js` вызывают `Favorite.continues(...)` как свойство
  объекта, а это тот же объект, что `Lampa.Favorite` (проверено и в собранном `app.min.js`, строка 10796).
  Плагин оборачивает `Lampa.Favorite.continues` и `category` у каждого источника в `Lampa.Api.sources`.
  Фильтр срабатывает, только когда `continues('tv')` вызвана **изнутри `category()`**. Вызовы из плеера
  (`player.js`) и Tizen возвращают полный список.
- **3.x (режим `rows`).** Внутреннюю `continues()` подменить нельзя (ТЗ это и отмечает), поэтому плагин
  оборачивает `Lampa.ContentRows.call`. Новые функции строк, добавленные этим вызовом, оборачиваются, а
  ответ меняется только у строки с заголовком `Lang.translate('title_continue')`. Данные фильтруются
  **до** создания карточек: `call({results})` получает уже отфильтрованный список.

Каталог, поиск, карточки, история и другие строки не меняются. Исходные объекты карточек тоже не
меняются. При любой ошибке возвращается исходный список.

### Решение «досмотрен ли сериал»

1. **Сериал:** `number_of_seasons || first_air_date` (тот же признак, что у Lampa). Нужен числовой TMDB id
   и источник `tmdb`/`cub`. Если источник не указан, оригинальное название сверяется с TMDB.
2. **Аниме** (`original_language == 'ja'` или японские символы в названии, как `Utils.containsJapanese`)
   по умолчанию **не обрабатывается** и не скрывается. Это меняется настройкой «Обрабатывать аниме».
3. **Вышедшие серии** берутся из TMDB: `tv/{id}` (сезоны, `last_episode_to_air`, `next_episode_to_air`)
   и `tv/{id}/season/{n}`. Учитываются серии с `air_date <= сегодня` (полночь по местному времени,
   как `Utils.parseToDate`). Будущие серии в расчёт не входят, но их ближайшая дата запоминается (`nextAir`).
4. **Сезон 0 (спецвыпуски)** не учитывается вообще: он не может ни скрыть сериал, ни помешать скрытию.
5. **Прогресс серии** ищется через `Lampa.Timeline.view(hash)`. Хеш формируется так же, как в самой Lampa:
   `Utils.hash([season, season > 10 ? ':' : '', episode, title].join(''))`. В качестве `title` пробуются
   `original_title` и `original_name`. В 3.x дополнительно используется `Timeline.watchedEpisode()`:
   она находит прогресс по привязке, если название карточки менялось. Серия досмотрена при прогрессе
   **≥ 90%** (настраивается: 80–100%). Почему 90: плеер Lampa не предлагает продолжить серию после 90%,
   ручная отметка «просмотрено» ставит 95, конец файла — 100.
6. **Сериал скрывается, только если** данные полны и непротиворечивы, а каждая вышедшая серия досмотрена.
   Во всех остальных случаях он остаётся в списке:
   - нет сезонов или не загрузился сезон;
   - есть серия без даты перед вышедшей;
   - `last_episode_to_air` не найдена в данных сезонов;
   - нет прогресса хотя бы одной серии;
   - ошибка сети или таймаут (20 с).

### Кеш и возврат после выхода новой серии

Строка строится синхронно, а TMDB отвечает асинхронно. Поэтому результат проверки хранится в
`localStorage['hws_cache']`, и строка фильтруется по нему. Постоянного списка скрытых нет: при каждом
построении строки сериал скрывается, только если одновременно:

- в кеше статус `complete`, и он моложе 7 дней (дальше не используется вообще);
- ещё не наступила `nextAir` — дата ближайшей известной серии. **Как только дата наступает, сериал
  возвращается сразу, даже без интернета**;
- каждая серия из сохранённого списка вышедших **сейчас** досмотрена по локальной истории. Если снять
  отметку «просмотрено», сериал вернётся сразу;
- в локальном расписании Lampa (`Lampa.TimeTable.get`) нет вышедшей серии, которой нет в списке и
  которая не просмотрена.

Повторные проверки в TMDB идут в фоне, по одной, без влияния на интерфейс:

- при старте Lampa и раз в 30 минут — для сериалов, которым она нужна;
- после изменения истории (`Timeline.listener` → `update`) — сериалы со статусом «не досмотрен»;
- `complete` — через 6 часов или при наступлении `nextAir` (так ловятся новые сезоны и изменения
  расписания);
- после ошибки — через 15 минут.

Если сеть пропала, уже подтверждённый `complete` остаётся в силе до `nextAir` или до 7 дней. Если
сериал ещё не проверялся, он не скрывается.

Ограничение: при самом первом показе сериала, которого нет в кеше (например, сразу после установки),
он остаётся в строке. Плагин проверяет его в фоне и скроет при следующем построении строки. Скрытые
сериалы не заменяются следующими из истории: Lampa отдаёт в строку не больше 19 элементов, и после
скрытия их становится меньше.

### Используемые API Lampa

`Lampa.Listener` (`app` → `ready`), `window.appready`, `Lampa.Favorite.continues`,
`Lampa.Api.sources.{tmdb,cub}.category` (2.3.0), `Lampa.ContentRows.call` (3.x), `Lampa.Timeline.view`,
`Lampa.Timeline.watchedEpisode` (3.x), `Lampa.Timeline.listener`, `Lampa.Utils.hash`, `Lampa.TimeTable.get`,
`Lampa.Storage.get/field`, `Lampa.Reguest`, `Lampa.TMDB.api/key`, `Lampa.Lang.translate`, `Lampa.SettingsApi`,
`Lampa.Noty`, `Lampa.Manifest.plugins`. Для массовой отметки дополнительно используются
`Lampa.Listener` (`full` → `complite`), `Lampa.Timeline.update`, `Lampa.Timeline.link` (3.x) и
`Lampa.Activity.all/active` с `activity.refresh()`.

Для запросов используется собственный экземпляр `Lampa.Reguest`. Общий сетевой объект источника
`tmdb` не подходит: Lampa очищает его при переходах между экранами, и колбэки тогда не вызываются.

Синхронизация с CUB: история читается через те же `Favorite.continues` / `Timeline.view`, что и у Lampa.
Они сами выбирают локальное хранилище или файл профиля `file_view_<id>`.

### Защита от повторной загрузки и циклов

- Флаг `window.__hws_installed`, а у каждой обёртки — ссылка `__hws` на оригинал. Повторная загрузка
  файла не создаёт второй обёртки, второго обработчика или вторых настроек (тест 13, R2).
- Сам по себе плагин в историю не пишет и строки не перерисовывает. Исключение — кнопка массовой
  отметки (см. ниже): она пишет в историю только по нажатию пользователя, а события `Timeline` от этих
  записей лишь ставят перепроверку в отложенную очередь, поэтому циклов нет.

## Массовая отметка вышедших серий (с версии 1.1.0)

На странице сериала (в ряду кнопок рядом с «Смотреть», «Избранное», «Реакции») появляется кнопка
**«Отметить все вышедшие серии просмотренными»**. Она доступна пультом, как остальные кнопки. В новом
интерфейсе Lampa подпись видна при фокусе.

Что происходит по нажатию:

1. Через тот же `tmdbGet`, что и у проверки, загружаются данные сериала из TMDB (`tv/{id}`), затем по очереди
   все обычные сезоны, в которых уже есть вышедшие серии (`planSeasons`: сезон 0 со спецвыпусками не
   учитывается).
2. Отмечаются только серии с известной и уже наступившей датой выхода (`air_date <= сегодня`). Будущие
   серии и серии без даты пропускаются и попадают в отчёт.
3. Каждая серия записывается штатно, так же как в торрентах и при отметке серии в самой Lampa:
   `Timeline.view(hash, Timeline.link(card, сезон, серия))`, затем `Timeline.update({hash, percent: 100, …})`.
   - Хеш — `Utils.hash([сезон, сезон > 10 ? ':' : '', серия, original_title].join(''))`. Если
     `original_name` отличается от `original_title`, пишется и второй хеш: под ним прогресс хранят
     карточки серий 3.x.
   - В Lampa 3.x в запись добавляется привязка `card/season/episode` из `Timeline.link()`: по ней Lampa
     находит прогресс, даже если название сериала поменяется. В 2.3.0 `Timeline.link` нет, поэтому
     запись идёт только по хешу — это и есть формат 2.3.0.
4. Серии, уже досмотренные (≥ порога из настроек, с учётом поиска по привязке), **не перезаписываются**:
   их время и длительность сохраняются. Частично просмотренные доводятся до 100%.
5. Запись идёт порциями по 20 серий, чтобы не подвешивать интерфейс телевизора.
6. Если сезон не загрузился, остальные сезоны всё равно отмечаются, а в уведомлении указаны номера
   незагруженных сезонов. Сериал в этом случае не скрывается, потому что данных недостаточно. Если не
   загрузился сам сериал или ни один сезон, выводится ошибка, а не «успех».
7. После записи состояние сериала сразу пересчитывается по свежим отметкам и данным TMDB, а у страниц
   «Главная»/«Сериалы» в истории переходов вызывается штатный `activity.refresh()`. Когда пользователь
   нажимает «Назад», страница пересоздаётся, и сериал исчезает из «Продолжить просмотр» — без очистки
   данных и переустановки.
8. Пока операция идёт, повторное нажатие не запускает вторую: показывается «Отметка серий уже
   выполняется, подождите».

Уведомления: «Отмечаю вышедшие серии…», затем, например, «Отмечено просмотренными: 16 серий, будущие
не отмечены: 4», «…уже были отмечены: 16», «Не загрузились сезоны: 2. Повторите позже», «Не удалось
отметить серии: нет связи с TMDB».

**Новые серии.** Флага «сериал просмотрен» нет: отмечаются конкретные серии, а будущие остаются
неотмеченными. Скрытие по-прежнему решается по отметкам каждой серии и актуальному списку вышедших
(дата следующей серии сохраняется в `nextAir`). Поэтому в день выхода новой серии сериал возвращается
в «Продолжить просмотр». Новая серия не отмечается сама — только если снова нажать кнопку.

Отменить массовую отметку можно только так же, как отдельную: снять отметку с серий в Lampa.

## Установка в Lampa 2.3.0 на LG webOS

Lampa подключает плагины по URL. Готового размещения у меня нет, поэтому файл нужно положить туда,
где его увидит телевизор.

**1. Разместить файл (любой вариант).**

- **GitHub + jsDelivr (рекомендуется).** Загрузите `hide_watched_series.js` в свой публичный репозиторий
  и используйте адрес `https://cdn.jsdelivr.net/gh/<пользователь>/<репозиторий>@main/hide_watched_series.js`.
  Подойдёт и GitHub Pages. Ссылка `raw.githubusercontent.com` **не подойдёт**: она отдаёт `text/plain`
  с `nosniff`, и браузер не выполнит скрипт.
- **Компьютер в той же сети.** В папке проекта выполните:

  ```bash
  node tests/integration/serve.js . 8790
  ```

  Адрес плагина: `http://<IP-компьютера>:8790/plugin/hide_watched_series.js`. Разрешите доступ в
  брандмауэре Windows. После первой успешной загрузки Lampa 2.3.0 хранит копию плагина в своём кеше
  (IndexedDB) и подключает её, если адрес недоступен (`plugins.js` → `createPluginDB`). Если Lampa на
  телевизоре открыта по `https://`, адрес `http://` будет заблокирован как смешанное содержимое — тогда
  используйте вариант с jsDelivr.

**2. Подключить в Lampa:** «Настройки» → «Расширения» → «Добавить плагин» → ввести адрес → OK.
Перезапустите Lampa.

**3. Проверить:** в «Настройках» появился раздел **«Просмотренные сериалы»**. Откройте раздел
«Сериалы» (в 3.x — главную) и подождите несколько секунд. Досмотренные сериалы исчезнут при следующем
открытии раздела.

### Настройки («Настройки» → «Просмотренные сериалы»)

| Параметр | Ключ | По умолчанию |
|---|---|---|
| Убирать досмотренные сериалы | `hws_enabled` | Да |
| Обрабатывать аниме | `hws_anime` | Нет: аниме не скрывается |
| Серия досмотрена при прогрессе от | `hws_threshold` | 90% |
| Режим отладки | `hws_debug` | Нет |
| Очистить данные плагина | — | удаляет кеш проверок |

## Удаление и очистка данных

1. «Настройки» → «Просмотренные сериалы» → **«Очистить данные плагина»**. Удаляется
   `localStorage['hws_cache']` — единственные данные, которые плагин создаёт сам.
2. «Настройки» → «Расширения» → на плагине удерживайте OK или нажмите OK дважды → «Удалить».
   Перезапустите Lampa.
3. Остаются только ключи изменённых настроек (`hws_enabled`, `hws_anime`, `hws_threshold`, `hws_debug`):
   короткие строки, без плагина они ни на что не влияют. Если есть доступ к консоли браузера
   (Lampa в браузере ПК, отладчик webOS), до удаления можно вызвать `HideWatchedSeries.purge()`:
   она удалит и кеш, и эти ключи.

Плагин не меняет закладки Lampa, а историю просмотра меняет только кнопкой массовой отметки. Сделанные
ею отметки — обычные записи прогресса Lampa, после удаления плагина они остаются. Остальное поведение
возвращается к стандартному.

## Отладка

1. Включите «Режим отладки».
2. Откройте встроенную консоль Lampa: в главном меню пункт «Консоль» или 10 раз нажмите «вверх» на
   верхней панели. Сообщения плагина собраны на вкладке **HideWatched**:
   - `started, version 1.1.0 mode legacy lampa 2.3.0` (на актуальной Lampa 3.x — `mode rows`; строки
     `row main …` в журнале означают именно режим `rows`);
   - `mark 247718 MobLand → ok marked: 16 already: 0 future: 4 undated: 0 failed seasons: -`;
   - `row category:tv items: 7 hidden: 4 Chernobyl | MobLand | …`;
   - `checked 247718 MobLand → complete all_watched next: Fri Oct 30 2026`;
   - `checked 1396 Breaking Bad → incomplete unwatched_last_s5e16`.
3. В консоли браузера: `HideWatchedSeries.status()` (состояние кеша по каждому сериалу),
   `HideWatchedSeries.stats()`, `HideWatchedSeries.mode()` (`legacy` / `rows` / `none`).

Причины в журнале: `all_watched`, `unwatched_s2e7`, `unwatched_last_…`, `no_seasons`, `season_missing_N`,
`undated_before_aired_…`, `last_episode_mismatch`, `details_network`, `details_timeout`, `title_mismatch`.
