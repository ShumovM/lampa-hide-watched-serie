Базовый commit: ветка `main`, `07a835f` (`style(ui): use green corner badge for watched items`). Документ актуализирован 27.11.2026 по локальной рабочей копии, включая незакоммиченную статистику и тесты. Он не подтверждает состояние живого проекта Supabase или настройки GitHub Pages.

## Назначение и компоненты

Плагин `hide_watched_series.js` (версия 1.5.0) скрывает из строки Lampa «Продолжить просмотр» сериалы, у которых просмотрены все уже вышедшие обычные серии. Когда выходит новая серия, сериал снова показывается; после просмотра снова скрывается. Дополнительно плагин добавляет массовую отметку вышедших серий, индивидуальные отметки фильмов, бейджи, кнопку продолжения с последней раздачи и необязательную синхронизацию через Supabase.

Основная функциональность работает без Supabase. Единственный клиентский файл — сам плагин; он написан на ES5 для старых движков webOS. Внешние библиотеки нужны только для тестов.

## Встраивание в Lampa

Плагин ожидает `window.Lampa` и запускается либо сразу при `window.appready`, либо по `Lampa.Listener.follow('app', ...)` после события `ready`. Точка входа — IIFE в `hide_watched_series.js`, функция `install()` инициализирует адаптеры, а `start()` регистрирует настройки, обработчики, бейджи и синхронизацию.

Поддерживаются две реализации строки «Продолжить просмотр»:

- **Lampa 2.3.0 (`legacy`)**: `patchLegacy()` оборачивает `Lampa.Favorite.continues()` и `category()` у `Lampa.Api.sources.tmdb/cub`. Фильтрация применяется только к `tv` во время построения категории. В этой версии строка находится в разделе «Сериалы».
- **Lampa 3.x (`rows`)**: `patchRows()` перехватывает `Lampa.ContentRows.call`; `wrapRow()` фильтрует результаты только строки, заголовок которой совпадает с `Lang.translate('title_continue')`. Вызовы не относящихся к этой строке списков пропускаются.

Если перехват невозможен или возникает ошибка фильтра, плагин сохраняет исходный список. Прочие строки/категории не должны фильтроваться.

Другие используемые API включают `Lampa.Timeline.view/update/link/watchedEpisode/listener`, `Lampa.TimeTable.get`, `Lampa.Storage.get/set`, `Lampa.SettingsApi`, `Lampa.Listener`, `Lampa.Reguest`, `Lampa.TMDB`, `Lampa.Lang`, `Lampa.Noty`, `Lampa.Activity` и `Lampa.Manifest`. Доступ к API проверяется защитными условиями и `try/catch`, поскольку версии отличаются.

## Логика скрытия сериалов

Чистые функции верхнего уровня (`planSeasons`, `evaluate`, `shouldHide`, `isFinished`, `needsCheck`) отделены от интеграции и экспортируются в `HideWatchedSeries.Core` для тестов.

1. `eligible()` допускает карточки сериалов с числовым id, подходящими источниками (`tmdb`/`cub`) и названием. Японское аниме исключено по умолчанию; его включает настройка.
2. `verify()` запрашивает TMDB `tv/{id}` и данные сезонов `tv/{id}/season/{n}`. Сезон 0 (спецвыпуски) не учитывается. Учитываются серии с известной датой выхода, уже наступившей на момент проверки. Неопределённые или противоречивые данные дают `unknown`, и карточка остаётся.
3. `makeIsWatched()` проверяет `Lampa.Timeline.view()` для хешей сериал/сезон/серия/название; в 3.x также использует `Timeline.watchedEpisode()`. Порог задаётся настройкой от 80% до 100%, default 90%.
4. `filterList()` применяет только свежую кешированную проверку. Запросы к TMDB выполняются асинхронно через очередь `enqueue()`/`pump()`, чтобы не задерживать построение строки. `tmdbGet()` имеет таймаут. Ошибки и нехватка данных не скрывают карточки.
5. Повторная проверка позволяет вернуть сериал после выхода серии. Кеш ограничен 300 карточками, результаты имеют soft/hard TTL, а новые данные истории помечают результат для проверки.

Основной кеш `localStorage['hws_cache']`, версия 1, объект `items` по TMDB id. Запись содержит статус/причину проверки, время проверки, требуемые серии и ближайшую дату выхода (набор конкретных полей находится в `store()`). Кнопка «Очистить данные плагина» очищает этот кеш, но не удаляет пользовательскую Timeline, отметки фильмов или записи раздач.

## Кнопки и бейджи

- `onFull()` распознаёт страницу фильма или сериала. Для сериала добавляет кнопку массовой отметки вышедших серий и «Продолжить», если известна последняя раздача. Для фильма добавляет «Отметить просмотренным»/«Снять отметку».
- `markAllAired()` загружает сериал и сезоны, обрабатывает записи порциями по 20 с отложенным продолжением, отмечает только вышедшие серии через `markEpisode()`. Она использует `Timeline.view/update` (и `Timeline.link` при наличии). Уже достигшие порога записи не переписываются. Это штатная Timeline Lampa, поэтому прогресс виден самой Lampa.
- `hws-watched-badge` — маленький зелёный треугольный уголок справа сверху постера с белой галочкой. `startBadges()` ставит `MutationObserver`, а при его отсутствии периодически сканирует DOM. `injectBadgeStyle()`, `scanBadges()` и `applyCardBadge()` обеспечивают один бейдж на карточку. Класс `hws-movie--on` используется на странице фильма. Тот же маркер показывается для сериала только если TMDB сообщает `Ended`/`Canceled`, нет будущих/недатированных серий и все вышедшие серии просмотрены (`isFinished()`).

## Статистика

В `SettingsApi` добавлен отдельный компонент «Статистика» с кнопкой «Открыть статистику». `showStats()` регистрирует `StatsScreen` через `Lampa.Component.add()` и открывает его как полноэкранную activity через `Lampa.Activity.push()`. Экран возвращает jQuery-разметку из `create()`/`render()` и сбрасывает флаг при `destroy()`. Этот экранный API используется вместо `Lampa.Modal.open()`, чтобы переход работал как навигация Lampa на телевизоре. Расчёт — `calculateStats()`; форматирование дней/часов/минут — `formatStatsDuration()`; сбор текущих данных — `viewingStats()`; HTML и оформление — `statsMarkup()`/`injectStatsStyle()`.

- Уникальные фильмы — объединение отметок `hws_movies_watched` по source/id и связанных Timeline-фильмов с прогрессом не ниже порога. Пара `cub`/`tmdb` приводится к одному источнику.
- Уникальные сериалы и аниме определяются по связанной Timeline-карточке и метаданным из `Favorite.get({type:'history'})`, а также по локально известному японскому оригинальному названию. Аниме исключено из счётчика сериалов. Сериал считается просмотренным для статистики при наличии хотя бы одной серии выше порога.
- Серии дедуплицируются по `(card, season, episode)`, а длительность для серии/фильма учитывается один раз. Записи без надёжного идентификатора или метаданных не относятся к точной категории; записи без `duration` увеличивают отдельный счётчик пропусков.
- Общее время — сумма известной полной `duration` у квалифицирующихся уникальных записей. Это длительность контента, не измерение фактически проведённого времени. Неизвестная длительность пропускается без подстановки.
- `refreshStatsScreen()` обновляет открытый экран после Timeline update, применения синхронизации или изменения отметки фильма. TMDB не запрашивается; схема, Edge Function и контракт Supabase Sync не менялись.

Старые Timeline-записи без `card`/`season`/`episode` нельзя надёжно связать и дедуплицировать, особенно после отметок в Lampa 2.3.0. Неопределённые строки исключаются и отражаются в предупреждении.

## Локальные данные

Данные, кроме очереди, хранятся в `localStorage`; Timeline принадлежит самой Lampa и читается/пишется через её Storage API.

| Ключ | Форма/назначение |
|---|---|
| `hws_enabled`, `hws_anime`, `hws_threshold`, `hws_debug` | Настройки фильтра, аниме, порога и отладки. |
| `hws_sync_url`, `hws_sync_code`, `hws_sync_id` | URL функции, общий `x-sync-code`, идентификатор группы; задаются пользователем отдельно на каждом устройстве. |
| `hws_cache` | `{v:1, items:{...}}`, кеш проверки сериалов (максимум 300). |
| `hws_movies_watched` | `{v:1, items:{"source_movieId":{t,title}}}`. Это отдельные отметки фильма, не закладки Lampa. |
| `hws_torrents` | `{v:1, items:{"source_seriesId":{title,magnet,link,hash,season,episode,t}}}` (максимум 200). `link`/`hash` остаются локальными. |
| `hws_sync_device_id` | Стабильный сгенерированный id установки/устройства. |
| `hws_sync_queue` | `{v:1, items:[{id,table,key,updated,row}]}` — локальная очередь повторной отправки. |
| `file_view` или `file_view_<profile>` | Файлы/ключи истории просмотра, принадлежащие Lampa; хеши связаны с прогрессом серий. Чтение делается по `Timeline.filename()` и `Storage.get()`. |

Конкретный профиль синхронизации вычисляется `syncProfile()` из `Storage.get('account')`, имени Timeline-файла или fallback `main`. Серверная область задаётся отдельным `sync_id` (по умолчанию `default`). Это строковый namespace, не аккаунт и не пароль.

## Supabase Sync: клиент и протокол

Синхронизация выключена, если не заданы URL и код. `syncStart()` запускает первый обмен через 6 секунд, далее раз в 5 минут, также после события `online`; локальные изменения планируют отложенный обмен. XMLHttpRequest (`syncRequest()`) асинхронный с timeout, не блокирует рендер списка. При ошибке очередь остаётся и назначается повторная попытка.

`syncQueueSnapshot()` сравнивает локальные Timeline/фильмы/torrent resume с полученной серверной историей и ставит отсутствующие или более свежие данные в очередь. `syncPullPage()` отправляет локальные изменения вместе с запросом `sync`, применяет возвращённые данные и дочитывает страницы. Базовый размер pull-страницы — 300 (на сервере до 500), push batch — 100 записей. Для пагинации используются курсоры `(sync_updated_at, естественный ключ)` и fallback offset для совместимого ответа без курсоров. `syncApplyRows()` не заменяет локальную запись более старой версией. Push после успешного ответа подтверждает и удаляет отправленные элементы очереди (`syncAck()`).

Локальные события:

- `onTimelineUpdate()` слушает `Lampa.Timeline.listener` событие `update`, сериализует изменившийся прогресс и добавляет `episode_progress` в очередь.
- `setMovieWatched()` пишет локальную отметку и очередь `movie_watched_marks`; отмена создаёт tombstone вместо простого удаления на сервере.
- `rememberTorrent()` вызывается после `torrent_file`, получает последнюю серию и magnet при доступности; добавляет `series_torrent_resume`, если есть magnet. При синхронизации не передаются приватный `link` и legacy `torrent_hash`.

При восстановлении Timeline плагин записывает запись в файл, полученный через `Timeline.filename()`, и вызывает `Timeline.read()`. Фильм восстанавливается в `hws_movies_watched`; torrent resume получает `magnet`, сезон и серию, но локальные `link` и хеш пусты. Офлайн-очередь переживает отсутствие сети, но не очистку устройства. Если до очистки изменения не успели попасть на сервер, они потеряны.

### Таблицы и поля БД

Миграция предназначена для уже существующих таблиц, описанных старой схемой проекта. Она не создаёт и не удаляет таблицы/строки. Сначала проверяет наличие таблиц и обязательных полей/типов, сохраняет `episode_progress.hash/road`, `client_updated_at BIGINT` и `movie_watched_marks.marked_at BIGINT`. Она добавляет в каждую таблицу `sync_id TEXT NOT NULL DEFAULT 'default'` и `sync_updated_at TIMESTAMPTZ NOT NULL DEFAULT epoch`, затем backfill-ит conflict-clock из старых timestamp-полей.

| Таблица | Базовые поля (старые записи сохраняются) | Дополнительно после миграции | Естественный ключ синхронизации |
|---|---|---|---|
| `episode_progress` | `id`, `profile_id`, `hash`, `road` (JSON с `percent/time/duration/profile/updated/card/season/episode`), `client_updated_at` (BIGINT), `deleted_at`, `device_id`, `updated_at` | `sync_id`, `sync_updated_at` | `(sync_id, profile_id, hash)` |
| `movie_watched_marks` | `id`, `profile_id`, `source`, `movie_id`, `title`, `marked_at BIGINT`, `deleted_at`, `device_id`, `updated_at` | `sync_id`, `sync_updated_at` | `(sync_id, profile_id, source, movie_id)` |
| `series_torrent_resume` | `id`, `profile_id`, `source`, `series_id`, `title`, `magnet`, `torrent_hash`, `season_number`, `episode_number`, `device_id`, `updated_at` | `sync_id`, `sync_updated_at` | `(sync_id, profile_id, source, series_id)` |

Миграция добавляет scoped unique и page indexes, проверяет дубликаты и завершится ошибкой, если найдёт неоднозначные естественные ключи. Для таблиц с обязательными legacy-колонками она настраивает безопасные defaults для insert через RPC. Она может удалить только старые natural-key unique constraints/indexes, которые не учитывают `sync_id`; первичные ключи и строки сохраняются. RPC `public.hws_sync_apply(...)` выполняет upsert с условием «только если входящий `sync_updated_at` новее»; для прогресса заполняет старые обязательные `hash/road/client_updated_at`, для resume — `torrent_hash` default. Доступ к RPC закрыт для `public/anon/authenticated`, execute даётся `service_role`.

Клиентский `episode_progress` wire row: `timeline_hash`, `percent`, `time`, `duration`, `profile`, `card`, `season`, `episode`, `updated_at`, `is_deleted`. RPC преобразует его в legacy `hash/road`. Для отметки фильма передаются `source`, `movie_id`, `title`, `marked_at` (milliseconds, BIGINT), `updated_at`, `is_deleted`. Для resume — `source`, `series_id`, `title`, `magnet`, `season_number`, `episode_number`, `updated_at`. Серверные идентификаторы `id` и `device_id`, а также `torrent_hash` клиенту не нужны. Функция возвращает нормализованный контракт, включая `updated_at` из `sync_updated_at`, а для Timeline переводит `road` обратно в прогрессные поля.

### Edge Function и авторизация

`index.ts` экспортирует список трёх таблиц и принимает только `POST` (кроме CORS `OPTIONS`). `x-sync-code` сравнивается constant-time с серверным `LAMPA_SYNC_CODE`. `serviceKey()` читает `SUPABASE_SECRET_KEYS` (включая ключ `default`) или `SUPABASE_SERVICE_ROLE_KEY`; ключ используется только сервером в заголовках Supabase REST. Секреты должны быть заданы в настройках Edge Function и отсутствуют в JS.

Поддерживаемые действия:

- `health`: `{success:true}` после проверки авторизации.
- `push`: принимает массивы изменений по трём таблицам (максимум 500 на таблицу), пишет через RPC и возвращает `{success:true}`.
- `sync`: записывает переданные изменения, затем возвращает `data`, `more`, `next` для постраничной выдачи каждой таблицы. Ошибки метода, JSON, auth, action, scope, конфигурации и PostgREST возвращаются JSON с HTTP-статусом; `OPTIONS` отвечает пустым `204` с CORS headers.

Параметры `sync_id` и `profile_id` валидируются и фильтруются вместе с таблицей; предел страницы 1–500. `toClientRow()` скрывает `link` и `torrent_hash`. Успешный ответ `sync` возвращает tombstones (флаги `is_deleted`), необходимые для согласования. `SUPABASE_URL`, `SUPABASE_SECRET_KEYS`/service key и `LAMPA_SYNC_CODE` — серверная конфигурация; в документе намеренно нет их значений.

## GitHub Actions, миграции и публикация

- `deploy-swift-task.yml`: запускается по push в `main` только при изменениях `supabase/functions/swift-task/**` либо вручную. Вызывает Supabase CLI deploy функции. Нужны GitHub Secrets `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`; checkout с `persist-credentials: false`, job имеет `contents: read`. Workflow не запускает SQL.
- `apply-supabase-migrations.yml`: только ручной `workflow_dispatch`; job продолжится лишь на ветке `main` и при включённом обязательном boolean `confirm_apply`. Использует `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`, `SUPABASE_DB_URL` и `supabase db push --remote="$SUPABASE_DB_URL" --yes`. Это отдельный workflow и не вызывается workflow деплоя функции.
- В репозитории нет workflow публикации клиентского JS. README указывает URL GitHub Pages `https://shumovm.github.io/lampa-hide-watched-serie/hide_watched_series.js`; вероятно, публикация завязана на внешнюю настройку Pages. Фактические настройки Pages в GitHub из файлов репозитория не устанавливаются.

Изменения функции и migration сами по себе не меняют внешний Supabase, пока соответствующий workflow не запущен. В частности, наличие migration-файла в Git не доказывает, что миграция уже применена к production.

## Тестирование

`package.json` определяет:

```sh
npm test
```

Команда последовательно запускает:

## Установка и ограничения

README задаёт plugin URL GitHub Pages, который добавляется в список плагинов Lampa. В плагине есть Supabase-настройки, но синхронизация требует их ручного заполнения на каждом устройстве и одинаковых `URL`, кода и `sync_id` для общей группы.

Фактические ограничения:

- Нет аутентификации Supabase Auth/идентификации владельца. Доступ к endpoint основан на общем `x-sync-code`; `sync_id` — только namespace, не средство защиты. Код не следует публиковать.
- Конфликт разрешается timestamp-ом `sync_updated_at`; синхронизация зависит от часов клиента и корректности backfill/server clock. Версия с более ранним timestamp не победит более позднюю.
- Данные, не отправленные до очистки localStorage, не восстановить из сервера; отдельно не синхронизируются настройки и кеш проверки сериалов.
- Магнет-ссылки синхронизируются как данные для возобновления. Torrent `link` и `torrent_hash` намеренно исключены; на другом устройстве запись может не восстановиться в точности, если магнит недоступен/неподдержан провайдером.
- При смене профиля синхронизация использует другой `profile_id`; совпадение фактического profile mapping между разными инсталляциями Lampa отдельно не проверено.
- Edge Function, migration и клиент должны быть совместимы; миграция проверяет базовую схему и может остановиться из-за отсутствующих полей или дублирующихся natural keys.
- По интеграционному отчёту версия 3.4.8 учтена для формы input-настроек, но полноценный прогон этой версии в отчёте отсутствует. Браузерная интеграция 2.3.0/3.4.4 зафиксирована; LG/webOS проверен владельцем только для перечисленных им сценариев.
- Текущая применённость SQL к живой Supabase, актуальность секретов, состояние Edge Function и настройки GitHub Pages нельзя подтвердить по локальным файлам.
